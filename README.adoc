`hyperpolymath/a2ml-ecosystem` coordinates implementations, tooling, CI
integrations, examples, and conformance fixtures for A2ML.

This repository is a satellite of `hyperpolymath/standards`. It does not own
the Attestation Markup Language (A2ML) specification or governance rules. The upstream specification and
governance authority are pinned in the https://github.com/hyperpolymath/standards repo

== Owned Here

* link:.machine_readable/descriptiles/ECOSYSTEM.a2ml[ECOSYSTEM.a2ml] records the member
  repository manifest.
* link:conformance/manifest.a2ml[conformance/manifest.a2ml] indexes the local
  positive and negative fixtures.
* link:scripts/check-membership.sh[scripts/check-membership.sh] checks that
  manifest entries, submodule declarations, and gitlinks stay aligned.
* `.github/workflows/anchor-drift.yml` runs anchor drift checks in CI.

== Not Owned Here

The A2ML specification is owned by `hyperpolymath/a2ml`, not by this hub and
not by `hyperpolymath/standards`. It was carved out of `standards` by
`24a12d6f` ("carve-out: evict a2ml, lol and the repo-guardian pair"); any
pointer still naming `standards` as the spec upstream resolves only inside a
frozen pin. Three surface dialects are pinned: `SPEC.adoc` (typed core +
markup surface), `RECORD-DIALECT-SPEC.adoc`, `MANIFEST-DIALECT-SPEC.adoc`.
See link:spec/README.adoc[spec/README.adoc] for the pins.

Governance remains owned by `hyperpolymath/standards` (`GOVERNANCE.adoc`).

== Machine-Readable Layout

Coordination metadata lives under `.machine_readable/` only:

* `anchors/ANCHOR.a2ml` — authority anchor and upstream pins.
* `descriptiles/ECOSYSTEM.a2ml` — membership manifest.
* `descriptiles/{STATE,META,PLAYBOOK,AGENTIC,NEUROSYM}.a2ml` — hub state, ADRs, playbook,
  and agentic / neuro-symbolic notes.

link:0-AI-MANIFEST.a2ml[0-AI-MANIFEST.a2ml] at the repository root is the entry
point that indexes this surface.

== Membership Layout

Member repositories are pinned as submodules under `members/<group>/<name>` on
their `main` branches. The groups are:

* `implementations`
* `tooling`
* `ci`
* `examples`
